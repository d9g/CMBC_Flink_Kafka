# CMBC_Flink_Kafka 项目讲解与关键知识点

## 一、项目概述

### 1.1 是什么

**统一数据实时导入系统**：从多个 Kafka 集群/多个 Topic 消费原始数据，经 Flink 流式转换后，写入下游 Kafka，产出符合**神策（Sensors Analytics）**格式的 JSON 数据。

- **Source**：Kafka（支持多集群、多 Topic）
- **Transformation**：元数据来自 MySQL，规则可配置、可插件化
- **Sink**：Kafka（正常数据 + 非法数据分 Topic）

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| 多源 Kafka | 多集群、多 Consumer Group、多 Topic，由 MySQL 元数据驱动 |
| 格式转换 | 默认 JSON；非 JSON 可通过插件转为 JsonNode（如 CSV → JSON） |
| 神策格式 | 将原始数据转为神策 track 格式（event、time、distinct_id、properties 等） |
| 用户关联 2.0 | 识别登录事件，生成 `$SignUp` / track_signup，支持多项目投递 |
| 字段映射 | 通过 MySQL 配置属性名、类型、神策侧字段名 |
| 不重不漏 | 从 MySQL 读取已提交 offset，重启后从上次位点续跑；支持按时间戳回溯 |

## 二、整体架构与数据流

### 2.1 数据流概览

```
                    ┌─────────────────────────────────────────────────────────┐
                    │                      FlinkMain                          │
                    │  ① 读 case 配置 → ② 读 application-*.properties         │
                    │  ③ 加载 MySQL 元数据 → ④ 计算每个源 topic 的起始 offset   │
                    └─────────────────────────────────────────────────────────┘
                                                      │
    ┌─────────────────────────────────────────────────┼─────────────────────────────────────────────────┐
    │                                                 ▼                                                 │
    │  Kafka Source (多集群/多 Topic)  ──►  CustomKafkaDeserializationSchema  ──►  Raw ConsumerRecord     │
    │         │                                    │                                                      │
    │         │  (同一条流上挂载)                    │  RichMapFunction                                        │
    │         ▼                                    ▼                                                      │
    │  OffsetWriter (Checkpoint 时写 MySQL)    按 server+topic 选 KafkaJsonConverter → JsonNode           │
    │                                                 │                                                      │
    │                                                 ▼                                                      │
    │  PropertiesMap (定时查 MySQL 元数据)  ──►  Broadcast  ──┐                                               │
    │                                                         │                                               │
    │                                                         │  connect + broadcast                          │
    │                                                         ▼                                               │
    │  JsonNode 主流  ──────────────────────►  TransFactory (BroadcastProcessFunction)                      │
    │                                              │  • 按 server+topic 选 JsonProcessor → SourceBaseEntity  │
    │                                              │  • SourceEventMessageConverter → 神策 SensorsEventBean   │
    │                                              │  • PostProcessor 判断是否登录事件 → 可选生成 $SignUp     │
    │                                              │  • 旁路：非法数据、Counter 统计                         │
    │                                              ▼                                                          │
    │  ┌──────────────────────────────────────────────────────────────────────────────────────────────┐   │
    │  │  主输出：正常事件 → Kafka (EventDataSchema)                                                    │   │
    │  │  旁路1：非法数据 → Kafka (InvalidEventDataSchema)                                             │   │
    │  │  旁路2：Counter  → RecordCounterWriter → MySQL                                                │   │
    │  └──────────────────────────────────────────────────────────────────────────────────────────────┘   │
    └─────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 入口与配置层级

1. **RDM / Case 配置**（`args[0]`，如 `case-dev.properties`）
   - 指定当前环境用哪份 application：`properties_file=application-dev.properties`
   - 可选：`start_timestamp`（按时间回溯）、`fail_on_cp_errors`、`kafka_producer_retries/ack`、`framework.streaming.appName`

2. **Application 配置**（如 `application-dev.properties`）
   - Kafka 消费/生产地址、Group、SASL、超时等
   - MySQL 连接与各类 SQL（源 Topic 映射、Sink 项目、属性映射、Counter、Checkpoint 表）
   - Flink：并行度、Checkpoint 间隔与目录、StateBackend（memory/fs/rocksdb）
   - 插件路由：`converter.xxx`、`processor.xxx`、`post.xxx`（key 为 `server.port.topic`，点号替换冒号）

3. **MySQL 元数据**
   - 源 ↔ 目标映射（哪个 Kafka+Group+Topic 对应哪个 Sink 项目）
   - 属性映射（原始字段 → 神策字段、类型）
   - Checkpoint 表（记录每个 Topic 的 partition/offset）
   - Counter 表（各阶段条数统计）

## 三、核心模块说明

### 3.1 FlinkMain（入口）

- 解析 case 配置，加载 `application-*.properties`，构建 `ParameterTool`。
- 配置执行环境：`ExecutionEnvUtil`（重启策略）、`CheckPointUtil`（Checkpoint 与 StateBackend）。
- 调用 `MetaDataUtil.loadAllMetaData` 从 MySQL 拉取一次元数据，构建 `kafkaSourceSink`（Kafka 源 → Sink 项目列表）。
- 调用 `RestartDuplicateUtil` / `StartFromSpecificOffsetUtil` 得到每个 (server, group, topic) 的 partition→offset，用于 `setStartFromSpecificOffsets`。
- 创建 Kafka Source（`KafkaGenerateFactory.createKafkaDataStream`）、广播流（`PropertiesMap`）、主处理（`TransFactory.processDataStream`）、三个 Sink（正常 Kafka、非法 Kafka、Counter 写 MySQL），最后 `env.execute(appName)`。

### 3.2 Kafka 连接层（KafkaGenerateFactory）

- **消费**：`FlinkKafkaConsumer` + `CustomKafkaDeserializationSchema`（直接返回 `ConsumerRecord<byte[],byte[]>`），再在 `RichMapFunction` 里按 `server + topic` 选择 `ConverterFamily` 中的 `KafkaJsonConverter`，得到 `JsonNode`；支持 SASL、指定 offset 起读。
- **生产**：`FlinkKafkaProducer` + `EventDataSchema` / `InvalidEventDataSchema` 将神策格式 / 非法数据写入对应 Topic。
- 同一条 Source 流上挂载 `OffsetWriter`，在 Checkpoint 时把当前消费到的 partition/offset 写入 MySQL。

### 3.3 元数据与广播（MetaDataUtil、PropertiesMap）

- **MetaDataUtil**：执行配置中的 SQL，拉取 SourceSink、SinkProject、Counter、PropertyMapping 等，返回 `Map<String, Object>`。
- **PropertiesMap**：实现 `SourceFunction<Map<String, Object>>`，按 `metadata.query.interval` 周期调用 `MetaDataUtil.loadAllMetaData` 并 emit，作为广播流。
- 主流的处理逻辑通过 `BroadcastProcessFunction` 使用这份“规则/元数据”，实现动态更新（无需改代码即可更新映射与规则）。

### 3.4 主处理（TransFactory）

- 使用 **BroadcastProcessFunction**：主流为 `JsonNode`，广播流为 `Map<String, Object>`（元数据）。
- **processElement**：
  - 从 `JsonNode` 中取 server、group、topic、partition；若是“Null Record”只打 Counter 并 return。
  - 用 `processor.{server}.{topic}` 从配置取处理器名，在 `ProcessorFamily.JSON_PROCESSOR_MAP` 中取 `JsonProcessor`，将 `JsonNode` 转为 `List<SourceBaseEntity>`（支持一拆多）。
  - 若 list 为空，视为非法，打 Counter 并 `ctx.output(invalidDataSideOutput, fullRecord)`。
  - 对每条 `SourceBaseEntity` 调用 `processSingleRecord`：用 `SourceEventMessageConverter` 转成神策 `SensorsEventBean`，补全 pa_key、date、partition/offset 等；再根据 `post.{server}.{topic}` 选 `PostProcessor` 判断是否登录事件，若是则生成 `$SignUp` 并投递；最后按 `projectId` 拆分多项目，每条带 `project` 字段输出。
- **processBroadcastElement**：把广播来的 `ruleMap` 放入 `BroadcastState`，并更新本地 `cache`，供 `SourceEventMessageConverter` 等使用。
- 全流程用 Flink Metrics 的 `Counter` 做阶段统计（SOURCE、INVALID、NEED_SPLIT、SPLIT、SIGNUP、SINK 等），通过旁路输出到 `RecordCounterWriter` 写 MySQL。

### 3.5 Checkpoint 与状态（CheckPointUtil、OffsetWriter）

- **CheckPointUtil**：根据配置选择 StateBackend（Memory / Fs / RocksDB）、开启 Checkpoint、EXACTLY_ONCE、间隔、超时、并发数、外部化保留、是否容忍 CP 失败等；并 `enableObjectReuse()`。
- **OffsetWriter**：实现 `CheckpointedFunction`，在 `snapshotState` 中把内存里维护的 (server, group, topic, partition) → offset 写入 Flink 状态，并同步写入 MySQL（insert checkpoint 表），实现“不重不漏”的位点持久化。

### 3.6 插件体系

| 插件类型 | 接口 | 作用 | 配置 key 示例 |
|----------|------|------|-------------------------------|
| 格式转换 | `KafkaJsonConverter` | ConsumerRecord → JsonNode（如 CSV→JSON） | `converter.{server}.{topic}=csvConverter` |
| 业务解析 | `JsonProcessor` | JsonNode → List&lt;SourceBaseEntity&gt; | `processor.{server}.{topic}=corpBankOldEvent` |
| 登录识别 | `PostProcessor` | SensorsEventBean → 是否登录事件 | `post.{server}.{topic}=uniLogPlatformPost` |

- 配置 key 中 `server` 的冒号需换成点号（如 `pubdev2.kafka.cmbchina.net.9093`）。
- 未配置时使用默认实现（如 `uniLogPlatformEvent`、`uniLogPlatformPost`）。

## 四、关键知识点整理

### 4.1 Flink 相关

| 知识点 | 在本项目中的体现 |
|--------|------------------|
| **StreamExecutionEnvironment** | 入口创建 env，配置重启策略、Checkpoint、全局参数，最后 `execute(appName)`。 |
| **Checkpoint 与 StateBackend** | `CheckPointUtil` 配置 Memory/Fs/RocksDB；EXACTLY_ONCE；外部化 Checkpoint 保留；RocksDB 可开增量。 |
| **BroadcastState** | 主数据流 `connect(广播流.broadcast(descriptor))`，在 `BroadcastProcessFunction` 中用广播流更新“规则状态”，主流的每条数据都能读到最新规则。 |
| **旁路输出（Side Output）** | `OutputTag` 定义 invalidData、counterList；在 `processElement` 里 `ctx.output(tag, value)`；主流 `getSideOutput(tag)` 再接 Sink。 |
| **KeyedBroadcastProcessFunction / BroadcastProcessFunction** | 本项目用 `BroadcastProcessFunction` 连接主流与广播流；注释中提到 keyby 是为了在需要时可使用 TimeService 注册定时器。 |
| **FlinkKafkaConsumer 起始位点** | `setStartFromSpecificOffsets(Map<KafkaTopicPartition, Long>)`，位点来自 MySQL 或按时间戳计算。 |
| **KafkaDeserializationSchema / KafkaSerializationSchema** | 消费侧自定义反序列化为 `ConsumerRecord`；生产侧自定义序列化神策 JSON。 |
| **CheckpointedFunction** | `OffsetWriter` 在 `snapshotState` 中持久化 offset 到状态并写 MySQL，在 `initializeState` 中恢复。 |
| **ParameterTool** | 从 properties 加载，`env.getConfig().setGlobalJobParameters(parameters)`，在 UDF 中可获取全局配置。 |
| **算子 uid / name** | 为关键算子设置 `name()`、`uid()`，便于作业升级与状态兼容。 |

### 4.2 Kafka 相关

| 知识点 | 在本项目中的体现 |
|--------|------------------|
| **多集群 / 多 Group** | 元数据中 (kafkaServer, consumerGroup, authString) 区分不同源，每个组合一个 FlinkKafkaConsumer。 |
| **指定 partition/offset** | 通过 `setStartFromSpecificOffsets` 实现从 MySQL 恢复或按时间戳回溯。 |
| **SASL 认证** | 通过 `CommonClientConfigs.SECURITY_PROTOCOL_CONFIG`、`SaslConfigs.SASL_MECHANISM`、`SaslConfigs.SASL_JAAS_CONFIG` 配置。 |
| **Producer 语义** | 配置 retries、acks（如 -1）配合 Flink Checkpoint 实现端到端语义。 |

### 4.3 数据与业务

| 知识点 | 在本项目中的体现 |
|--------|------------------|
| **神策 track 格式** | event、time、distinct_id、properties 等；支持 track、track_signup（$SignUp）、用户关联 2.0。 |
| **一拆多** | `JsonProcessor` 返回 `List<SourceBaseEntity>`；按 `projectId` 再拆成多条带不同 `project` 的事件。 |
| **元数据驱动** | 源 Topic、Sink 项目、属性映射、Counter/Checkpoint 表结构均由 MySQL + SQL 配置，便于多环境、多租户。 |
| **非法数据隔离** | 解析失败或校验不通过的数据打上错误原因，通过 Side Output 写入独立 Topic，便于排查与重跑。 |

### 4.4 工程与设计

| 知识点 | 在本项目中的体现 |
|--------|------------------|
| **双配置体系** | Case 配置（RDM/环境） + Application 配置（Kafka/MySQL/Flink/插件路由），环境与配置分离。 |
| **插件化** | Converter / Processor / PostProcessor 接口 + 配置 key 路由，新增数据源或格式只需加实现类与配置。 |
| **单例** | `TransFactory.getInstance()` 单例提供主处理逻辑。 |
| **配置 key 规范** | `server.port.topic` 中冒号替换为点号，避免 properties 解析问题。 |

## 五、配置与运行小结

- **运行入口**：`com.sensorsdata.analytics.FlinkMain`，参数为 case 配置文件路径（如 `src/main/resources/case-dev.properties`）。
- **Case 配置**：至少包含 `properties_file=application-dev.properties`，其余可选。
- **Application 配置**：需正确配置 Kafka、MySQL 及各类 SQL；Checkpoint 目录、StateBackend 按环境选择（本地可用 `file:///tmp/...`，生产多用 HDFS + RocksDB）。
- **MySQL**：需存在对应表结构（offset 表、counter 表、属性映射表等），并与配置中的 SQL 一致。

以上即为本项目的整体讲解与关键知识点整理，便于理解架构、数据流和扩展方式。
